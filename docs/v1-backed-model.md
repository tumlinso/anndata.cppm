# Backed-model cleanup

This note records the backed-model changes against the frozen review source under `build/v1-cleanup/baseline-source`. The [review](review/backed-model.md) retains the original evidence and recommendations. Correctness and build results are reported separately; no runtime or build-speed claim follows from these source changes.

- **B01 — validation adapters:** `BorrowedBackend` forwards record numeric and bounded-string reads and rejects record writes; `Sink` accepts record creation and writes so `validate_all()` reaches source validation. The record regression covers validation-mode overrides in both directions, same-mode round trips, scalar and empty records, and malformed UTF-8. The destination backend still decides whether records are supported.
- **B02 — page refill:** a spilled category plan invalidates its page marker before reading and publishes it after the complete read. A Linux 64-bit HDF5 regression injects an error into the anonymous mapping-file read and retries the same retained plan. Category plans shared by handles retain mutable paging state; callers synchronize access to the shared plan. No per-value lock was added.
- **B03 — string batches:** `read_strings_all` and packed string-array reading share a private concrete-callable traversal. Output-specific validation, packing, prefix accounting and bounds remain separate. Scalar, empty, and selected arrays still use the same bounded backend admission; the adjacent-run check now avoids `size_t` addition overflow.
- **B04 — UTF-8:** `src/utf8.hpp` supplies a private UTF-8 invariant check shared across module and non-module implementation files. Read, streamed-copy and writer boundaries retain their own validation gates, error codes, paths and NUL policy. It is not a public header.
- **B05 — POSIX spill boundary:** category temporary-file operations are grouped under a private POSIX adapter; index uniqueness spill documents its `fseeko`/`ftello` dependency. Non-POSIX targets still need an implementation with matching transfer, offset and cleanup semantics.
- **B06 — code dispatch:** streamed categorical-code validation resolves integer type once before processing runs; range, missing-sentinel and unsigned overflow checks remain in the typed loop. `Validation::none` retains its prior early return. A regression exercises all eight integer widths, signed missing and invalid codes, dictionary bounds, and unsigned overflow across full and none modes.
- **B07 — preflight:** whole-dataset initialization performs complete validation before writing, then propagates that private prevalidated state through its child writers. Direct structural element writes retain their checks. As with other borrowed aliases, callers keep the source stable throughout a synchronous write; modifying it during backend I/O no longer receives incidental repeated validation. String-category text validation duplicated within one preflight is also removed.

Staging budgets remain transfer budgets rather than total process-memory limits. HDF5 and Zarr interoperability requires their existing independent fixture tests; caller-controlled execution and backend-specific thread-safety requirements still apply.

An independent `/tmp/make_utf8_diff.py` differential harness compared the shared decoder against the three frozen model recognizers on 18,153,739 byte strings, including every string of length 0–3 and all four-byte combinations with F0–F4 leads and continuation bytes. The acceptance results agreed; all copy-decoder error categories were compared, with the original throwing function directly checked on length 0–2 and longer targeted cases. This covers the UTF-8 recognizer only, not the writer's separate NUL policy or whole-store interoperability. The temporary harness is not a tracked test.
